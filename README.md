# 청춘주막 QR 주문 시스템 — 배포 가이드

이 가이드를 순서대로 따라하면 별도 서버 없이 **Google Sheets + Apps Script + GitHub Pages(또는 Vercel)** 만으로 축제 당일 사용할 수 있는 QR 주문 시스템이 완성됩니다.

전체 흐름: `손님 스마트폰 → index.html(정적 페이지) → Apps Script 웹앱 → Google Sheets`

---

## STEP 1. Google Sheets 만들기

1. [sheets.google.com](https://sheets.google.com) 에서 새 스프레드시트를 만들고 이름을 `청춘주막 주문관리` 등으로 지정합니다.
2. 상단 메뉴에서 **확장 프로그램 > Apps Script** 를 클릭합니다.
3. 편집기가 열리면 기존 `Code.gs`(myFunction 만 있는 기본 파일) 내용을 **전부 지우고**, 이 프로젝트의 `Code.gs` 파일 내용을 그대로 붙여넣습니다.
4. 저장(Ctrl+S / Cmd+S)합니다.

## STEP 2. 초기 시트 자동 생성

1. Apps Script 편집기 상단에서 함수 선택 드롭다운을 `initializeSheets` 로 변경합니다.
2. **실행(▶)** 버튼을 클릭합니다.
3. 처음 실행 시 권한 승인 화면이 뜹니다 → `권한 검토` → 본인 구글 계정 선택 → `고급` → `(안전하지 않음) 내 프로젝트로 이동` → `허용`.
   - 이는 본인이 만든 스크립트를 본인 시트에 연결하는 것이므로 정상적인 절차입니다.
4. 실행이 끝나면 알림창이 뜨고, 스프레드시트에 아래 4개 탭이 자동 생성됩니다.
   - `메뉴관리` (샘플 메뉴 9개 포함)
   - `주문내역`
   - `주문아이템로그` (통계 집계용 보조 탭 — 지우지 마세요)
   - `실시간통계` (수식 자동 삽입 완료)
5. `메뉴관리` 탭을 열어 실제 판매할 메뉴로 내용을 수정하세요.
   - **품절여부** 열은 `TRUE`/`FALSE` 만 입력 (체크박스로 만들어도 됨: 해당 열 선택 → 데이터 > 데이터 확인 > 체크박스)
   - 메뉴를 새로 추가할 땐 `메뉴ID`만 겹치지 않게 채워주면 됩니다 (예: A04, B05 ...)
   - **축제 당일에도 이 탭만 수정하면 손님 화면에 바로 반영됩니다** (재배포 불필요)

> **카테고리별 배경색은 `initializeSheets()` 실행 시 자동으로 적용됩니다.** (안주류=파랑, 음료/주류=빨강, 사이드=노랑 순서로 자동 배정) 새 메뉴를 같은 카테고리로 추가하면 자동으로 같은 색이 입혀집니다. 만약 **새로운 카테고리**(예: "디저트")를 추가했다면, Apps Script 편집기에서 함수 선택을 `refreshCategoryColors`로 바꿔서 한 번 실행해주면 새 카테고리에도 색이 배정됩니다.

> `실시간통계` 탭은 `initializeSheets()` 실행 시 자동으로 수식이 채워집니다. 혹시 직접 확인/수정하고 싶다면 아래 수식을 참고하세요.

| 항목 | 참조 탭 | 수식 요지 |
|---|---|---|
| 총 매출 | 주문내역 | `=SUM(주문내역!E2:E)` |
| 메뉴별 TOP3 | 주문아이템로그 | `QUERY(...group by 메뉴명 order by sum(매출) desc limit 3)` |
| 메뉴별 전체 판매량/매출 | 주문아이템로그 | `QUERY(...group by 메뉴명 order by sum(매출) desc)` |
| 테이블별 누적 금액 | 주문내역 | `QUERY(...group by 테이블번호)` |
| 시간대별 주문 건수 | 주문내역 | `QUERY(...group by hour(타임스탬프))` |

입금 확인이 끝난 주문은 `주문내역` 탭의 **입금확인여부** 셀을 `미확인` → `확인`으로 직접 바꿔주면 됩니다 (드롭다운으로 만들고 싶다면 해당 열에 데이터 확인 규칙을 추가하세요).

## STEP 3. Apps Script 웹앱으로 배포 (CORS 처리 포함)

1. Apps Script 편집기 우측 상단 **배포 > 새 배포**를 클릭합니다.
2. 톱니바퀴(⚙) 아이콘을 눌러 유형 선택 → **웹 앱** 선택.
3. 설정값:
   - **설명**: `jumak-order-v1` (아무 이름이나 무방)
   - **다음 사용자 권한으로 실행**: **나(본인 계정)**
   - **액세스 권한이 있는 사용자**: **모든 사용자 (Anyone)** ← 반드시 이 옵션이어야 손님이 로그인 없이 접근 가능합니다.
4. **배포** 클릭 → 권한 승인 한 번 더 진행 (STEP 2와 동일).
5. 배포가 끝나면 `https://script.google.com/macros/s/AKfycb.../exec` 형태의 **웹 앱 URL**이 발급됩니다. 이 URL을 복사해두세요.

### CORS(교차 출처) 관련 중요 안내

Google Apps Script 웹앱은 브라우저의 **preflight(OPTIONS) 요청을 지원하지 않습니다.** 그래서 프론트엔드에서 `Content-Type: application/json` 으로 요청을 보내면 CORS 에러가 발생합니다.

이 프로젝트의 `index.html`은 이를 우회하기 위해 다음과 같이 처리되어 있습니다 (이미 코드에 반영되어 있으므로 별도 작업 불필요):

- 주문 전송 시 `Content-Type: text/plain;charset=utf-8` 으로 전송 → 브라우저가 "simple request"로 판단해 preflight를 생략함
- 서버(`Code.gs`)의 `doPost`에서 `e.postData.contents`를 `JSON.parse()`로 직접 해석

**메뉴 조회(`doGet`)는 GET 요청이라 원래 CORS 문제가 없습니다.**

> 만약 코드를 수정하다가 CORS 에러(`Access-Control-Allow-Origin`)가 다시 발생한다면, fetch의 `Content-Type`을 `application/json`으로 바꾸지 않았는지, 또는 배포 시 "액세스 권한: 모든 사용자"로 설정했는지 다시 확인하세요.

### 메뉴/코드 수정 후 재배포 방법

`Code.gs`를 수정한 뒤에는 **배포 > 배포 관리 > 연필(✏) 아이콘 > 버전: 새 버전 > 배포** 를 눌러야 실제 URL에 변경사항이 반영됩니다. (URL 자체는 바뀌지 않습니다.)

## STEP 4. 프론트엔드(index.html) 설정

1. `index.html` 파일을 열고 상단 `CONFIG` 객체를 실제 정보로 수정합니다.

```js
const CONFIG = {
  SCRIPT_URL: "여기에_STEP3에서_복사한_웹앱_URL_붙여넣기",
  SHOP_NAME: "청춘주막",
  BANK_NAME: "카카오뱅크",
  ACCOUNT_NUMBER: "3333-01-1234567",
  ACCOUNT_HOLDER: "홍길동",
  MAX_TABLE: 30,
};
```

2. 저장합니다.

---

## STEP 5. GitHub Pages로 호스팅하기

1. GitHub에서 새 저장소(Repository)를 만듭니다. (예: `jumak-order`)
2. `index.html` 파일을 저장소 루트에 업로드합니다. (드래그 앤 드롭 또는 git push)
3. 저장소 **Settings > Pages** 로 이동합니다.
4. **Source**를 `Deploy from a branch`로 설정 → Branch: `main`, 폴더: `/(root)` 선택 후 저장.
5. 1~2분 후 `https://[깃허브아이디].github.io/jumak-order/` 형태의 주소가 생성됩니다.

## STEP 6. 테이블별 QR 코드 생성

각 테이블 URL은 아래와 같이 `?table=` 파라미터만 바꿔주면 됩니다.

```
https://[내주소]/index.html?table=1
https://[내주소]/index.html?table=2
https://[내주소]/index.html?table=3
...
```

QR 코드는 아래와 같은 무료 서비스로 손쉽게 생성할 수 있습니다.
- [QR Code Generator](https://www.qr-code-generator.com/)
- Google "qr code generator" 검색 후 원하는 무료 툴 사용

생성한 QR 이미지를 테이블 번호 스티커와 함께 인쇄해서 각 테이블에 부착하면 됩니다. 만약 손님이 QR을 못 찍거나 파라미터 없이 접속해도, 앱이 자동으로 **테이블 번호 선택 모달**을 띄워주므로 걱정하지 않으셔도 됩니다.

## STEP 7. 최종 점검 체크리스트

- [ ] `메뉴관리` 탭에 실제 판매 메뉴/가격이 정확히 입력되어 있는가
- [ ] Apps Script 웹앱 배포 시 "액세스 권한: 모든 사용자"로 설정했는가
- [ ] `index.html`의 `SCRIPT_URL`, 계좌 정보가 실제 값으로 채워져 있는가
- [ ] 실제 스마트폰(다른 계정, 시크릿 모드 등)으로 접속해서 주문 → 시트에 정상 반영되는지 테스트했는가
- [ ] `주문내역` 탭에 새 주문이 실시간으로 쌓이는지 확인했는가
- [ ] `실시간통계` 탭의 수식이 정상적으로 값을 보여주는지 확인했는가
- [ ] 축제 당일 담당자가 `입금확인여부` 열을 수동으로 갱신할 동선을 정했는가

## 자주 발생하는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|---|---|
| 메뉴가 로딩 화면에서 멈춤 | `SCRIPT_URL`이 잘못됐거나, 배포 시 "모든 사용자" 권한이 아님. 배포 관리에서 재확인 |
| 주문 시 CORS 에러 | fetch의 Content-Type을 `application/json`으로 바꾸지 않았는지 확인 (반드시 `text/plain`) |
| 주문번호가 중복됨 | `LockService`가 적용되어 있으나, `Code.gs`를 임의 수정했다면 `saveOrder` 함수의 lock 처리가 유지되는지 확인 |
| 시트 수정했는데 반영 안 됨 | `메뉴관리` 탭 수정은 즉시 반영되지만, `Code.gs` 자체를 수정했다면 재배포(새 버전) 필요 |
| 통계 수식이 `#N/A` 또는 오류 | 주문이 아직 없어서 발생하는 정상적인 상태. 테스트 주문을 한 번 넣어보면 해결됨 |
